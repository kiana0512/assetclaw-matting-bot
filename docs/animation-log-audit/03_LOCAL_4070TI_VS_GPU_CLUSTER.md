# 03 本机 4070 Ti 与 GPU 集群速度对比

## 1. 审计结论

在当前可用的成功视频样本中，**集群整体表现基本符合“约 3 倍”的工程预期，但波动较大，不能认为每个任务都必然是 3 倍。**

| 指标 | 本机 4070 Ti | GPU 集群纯执行 | 加速比 |
|---|---:|---:|---:|
| 样本数 | 8 | 12 | — |
| 吞吐中位数 | 0.556 帧/分 | 1.532 帧/分 | 2.75× |
| 吞吐均值 | 0.704 帧/分 | 2.063 帧/分 | 2.93× |
| P90 吞吐 | 1.095 帧/分 | 3.711 帧/分 | 不直接相除 |

这里的集群值只使用 `remote started_at → finished_at`，不含客户端上传、远端排队、结果回传和本地解压；本机值使用逐 prompt 实际时间。因此它比当前页面的“含排队”指标更接近 GPU 算力对比。

## 2. 最近三节点样本

| 任务 | 帧数 | 节点数 | 纯 GPU 时间 | 吞吐 | 相对本机中位数 |
|---|---:|---:|---:|---:|---:|
| `VID_8DE68A9E8025` | 97 | 3 | 40分00秒 | 2.425 帧/分 | 4.36× |
| `VID_5B1FF7F20EA1` | 97 | 3 | 36分46秒 | 2.638 帧/分 | 4.74× |

这两个近期任务速度正常，甚至高于“3 倍”预期。它们的节点分配分别为 55/27/15 与 42/27/28 帧，第一条不够均衡但仍完成得较快。

## 3. 为什么不能只看节点数

现有 12 个集群视频中：

- 2 节点样本 5 个，中位数 1.819 帧/分；
- 3 节点样本 7 个，中位数 1.512 帧/分。

这不代表“两节点比三节点快”。样本任务、分辨率、缓存状态、同时负载和帧数不同，且 2 节点组里有两个 4.7 帧/分左右的快样本，把中位数抬高。当前数据不满足按节点数做因果结论的条件。

另外，集群是 4090 + 3090 + 3090 的异构组合，本机是 4070 Ti。三节点总理论算力本就不严格等于三台 4070 Ti；调度粒度、模型加载、慢节点拖尾和显存压力都会改变倍率。

## 4. 明确的慢集群异常

`VID_9D9EB9ACE6A1`：97 帧、2 节点，远端排队只有 0.60 秒，但纯 GPU 执行 1时22分17秒，吞吐 1.179 帧/分。

对比同为 97 帧的集群任务：

- `VID_589E7DC50376`：约 25分20秒，约 3.83 帧/分；
- `VID_1B6A58300CBD`：约 53分20秒，约 1.82 帧/分；
- 最近三节点两条：36–40 分钟，2.42–2.64 帧/分。

该任务不是排队慢，而是执行期慢。需要按节点检查：单节点每帧时间、GPU 利用率/功耗、显存换页、是否并发其他批次、输入分辨率、模型/工作流版本、失败重试与最后一个分片拖尾。

## 5. 本机历史长尾的真实含义

多个本机视频在父任务创建后等待 11–14 小时才进入 ComfyUI；这些时长目前被页面标成“任务创建与抽帧”。实际抽帧通常只有数秒，长段更像本地单 GPU 串行队列等待。因为没有 `matte_queue_entered` 与 `extract_finished` 独立时间点，不能据此声称 FFmpeg 抽帧慢。

## 6. 建议的正式 A/B 基准

为了最终回答“集群是否稳定达到 3 倍”，应增加可重复实验：

1. 固定同一批 100 帧素材，记录每帧宽高与总像素。
2. 固定同一 workflow、模型、精度、输出格式与软件 commit。
3. 本机与集群分别冷启动 1 次、热启动 5 次。
4. 集群分别强制 1/2/3 节点；实验期间记录其他并发批次。
5. 同时记录 wall time、GPU execution、秒/帧、Mpixel/s、节点分片、节点 P50/P95 帧延迟、失败重试。
6. 用总帧数/总 GPU 秒计算加权吞吐，另报告按任务的中位数，避免小任务权重过高。

验收建议：三节点热启动的加权吞吐至少达到本机 2.7×，P90 单任务加速不低于 2.2×，并且节点拖尾占比低于 15%。达不到时再做调度或工作流优化。
