# 动画管家全量日志审计

审计日期：2026-07-30（Asia/Shanghai）  
审计范围：现有工作区可发现的直发任务、动画流程状态文件及 SQLite 运行记录。

## 结论先行

1. **当前分析页不是全量分析。** 截图中的“43 个任务 / 36 个成功样本 / P50 9分51秒”可精确复现为：最新 20 个图片父任务、最新 20 个视频父任务、3 个非调试动画流程。图片窗口最早到 7 月 29 日，视频窗口却最早到 7 月 25 日，统计窗口不对称，也没有在页面标明。
2. **全量直发成功率为 83.3%。** 共 150 个直发父任务：125 DONE、19 FAILED、6 CANCELED。图片直发 42/49 成功，序列帧 ZIP 42/54 成功，视频直发 41/47 成功。
3. **一键动画流程当前不可用。** 26 个流程中 17 FAILED、9 CANCELED、0 DONE；其中 15 个失败为 worker 退出后清理僵死状态。所有流程的阶段对象都缺少可计算的开始/结束时间，无法做七步耗时审计。
4. **GPU 集群整体接近预期，但不能简单判定“恒定 3 倍”。** 在可比的成功视频样本上，本机 4070 Ti 的中位吞吐为 0.556 帧/分，集群纯 GPU 执行中位数为 1.532 帧/分，中位加速比 2.75×；按均值为 2.93×。最近两个 97 帧、三节点任务达到 2.425 与 2.638 帧/分，相对本机中位数是 4.36× 与 4.74×。
5. **集群排队不是当前主要瓶颈。** 12 个可拆分的视频集群样本，远端真实排队中位数 0.61 秒、P90 1.05 秒；当前页面显示的 handshake `queue_depth` 是全局队列深度，不是该任务的排队时间。
6. **发现严重“空转/恢复间隔”异常。** 两个单图任务耗时约 41 小时，但实际 Cherry 执行仅约 30 秒；一个 171 帧视频耗时 40 小时 26 分，其中后处理实际执行约 41 分钟，其余约 38 小时 24 分是执行间隔。当前页面会把整段都标成 Cherry 后处理，归因不准确。
7. **飞书入口到附件落盘仍不可量化。** 当前 `created_at` 从动画管家父任务创建开始；没有“飞书事件抵达”和“附件下载完成”两个独立、可靠的业务时间点。文件 mtime 只能作为弱代理，不能声称是完整用户端到端耗时。
