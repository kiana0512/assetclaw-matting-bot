# 04 异常、失败与可靠性审计

## 1. 最高优先级异常

### A. 后处理空转约 38–42 小时

| 任务 | 类型 | 总耗时 | Cherry 包络 | Cherry 实际运行 | 空转/恢复间隔 |
|---|---|---:|---:|---:|---:|
| `IMG_65E2185AA833` | 单图 | 41时46分27秒 | 41时44分34秒 | 29.8秒 | 41时44分04秒 |
| `IMG_288AA489B664` | 单图 | 41时43分51秒 | 41时41分58秒 | 30.0秒 | 41时41分28秒 |
| `VID_BD18EE2C8C8F` | 171帧视频 | 40时26分32秒 | 39时05分42秒 | 41分14秒 | 38时24分27秒 |

这三条的瓶颈不是 Cherry 算法执行速度，而是尝试之间的超长非运行间隔，可能对应 worker 离线、进程重启、任务恢复或调度状态卡住。当前页面用最早 attempt 到最晚 attempt 作为后处理耗时，会错误地把整段归因给 Cherry。

处理建议：把 `active_attempt_sum` 与 `idle_gap` 分开展示；idle gap 超过 5 分钟立即告警并记录 worker heartbeat、重启原因和恢复人/进程。

### B. 小 ZIP 投递异常

`IMG_D48264D8B767` 仅 2 帧，总耗时 11分52秒：抠图 3分13秒，Cherry 9.7秒，投递段 8分27秒。投递时间远高于任务体量，应检查飞书上传重试、限流、网络阻塞和“已上传但未写回 receipt”的状态机。

### C. 集群执行慢点

`VID_9D9EB9ACE6A1` 的远端排队仅 0.60 秒，97 帧纯 GPU 执行却为 82分17秒，吞吐 1.179 帧/分。异常发生在执行期，不应优化队列。优先查节点级 telemetry 与最后一个分片拖尾。

### D. 历史本机等待被误标为抽帧

`tasha_walk` 等多个视频在任务创建后等待 11–14 小时才创建/握手 ComfyUI。缺少独立队列事件导致它们被归入“创建与抽帧”。这属于可观测性归因异常；在补齐事件前不应针对 FFmpeg 做优化结论。

## 2. 直发失败结构

### 序列帧 ZIP：11 FAILED + 1 CANCELED

主要失败簇是本地 ComfyUI 单 prompt 600 秒未完成，随后输出校验重试 3 次仍失败。样本常在第一帧或处理中途触发，说明当前问题集中于：

- 单帧超时阈值固定，不区分分辨率/模型负载；
- prompt 卡死后只是重试同一路径，缺少进程级熔断与换后端；
- 大批次没有 checkpoint/requeue，单帧失败使整批任务失败；
- 本地 worker 队列与 GPU 健康度缺少联动。

建议：单帧失败后重启/健康检查 ComfyUI，再把失败帧单独重排；已完成帧继续复用；达到阈值后自动切集群，避免整包重做。

### 视频：2 FAILED + 4 CANCELED

- `VID_A9AC71B12E82`：50 帧完成 25 帧后，第 26 帧 prompt 600 秒超时。
- `VID_965D132E14F5`：111 帧只完成 2 帧，Comfy run 进入 CANCELED。
- 其余 4 条是取消，现有快照没有统一 `cancel_reason`，无法区分用户取消、系统熔断或进程恢复清理。

### 图片直发：6 FAILED + 1 CANCELED

- `matte_dir` 无输出图：2 条；
- Cherry 浏览器多次启动失败：2 条；
- worker 退出后清理僵死状态：1 条；
- 等待角色确认超时（提醒 2 次）：1 条；
- 取消原因空白：1 条。

建议把“用户等待/确认超时”从系统失败中分离为 `EXPIRED_USER_WAIT`，否则失败率会混合产品交互与计算可靠性。

## 3. 一键动画流程：当前最大可靠性问题

| 状态 | 数量 | 主要原因 |
|---|---:|---|
| DONE | 0 | — |
| FAILED | 17 | 15 条 worker 退出/僵死清理；2 条飞书表格凭据或权限问题 |
| CANCELED | 9 | 快照未统一记录取消原因 |

所有 26 个流程的 stage 都没有成对 `started_at/finished_at`，因此目前无法回答抽帧、抠图、后处理、打包和回传各花多久。流程先要恢复到可成功完成，再做性能优化；否则性能统计没有成功基线。

## 4. 数据质量异常

- 125 个 DONE 中仅 20 个有可发现的持久投递回执；这不证明其余 105 个没发送，只说明系统无法事后证明。
- 10 个成功任务的阶段时间点不单调或阶段和超过父任务生命期；它们已从阶段基线剔除。
- 状态 JSON 为最终快照，缺少重启、重试、暂停和恢复的追加事件。
- 取消任务普遍缺 `cancel_reason` 与 `canceled_by`。

## 5. 告警优先级

| 优先级 | 条件 | 自动动作 |
|---|---|---|
| P0 | 动画流程 worker heartbeat 丢失、流程无成功 | 停止接新流程、重启 worker、保留现场、通知值班 |
| P1 | active attempt 间隔 >5分钟、单 prompt >600秒、投递 >5分钟 | 标记任务异常、健康检查、可恢复重排 |
| P1 | 成功任务无 delivery ack | 查询飞书/云盘结果并补写回执，禁止静默 DONE |
| P2 | 秒/帧超过同版本同分辨率 P95 或 MAD Z>3.5 | 标注异常节点/版本并加入诊断队列 |
| P2 | 节点拖尾 >15% | 调整分片或 speculative retry |
