# 05 现有分析页面差距审计

## 1. 现有页面做得好的部分

- 已经把父任务端到端、阶段条、P50/P90、吞吐、最慢阶段和单任务明细组织到一个可操作界面。
- 对缺失飞书入口时间没有伪造数值，页面明确提示“飞书入口等待暂未计入”。
- 能区分视频、图片/ZIP，并保留任务级证据，适合作为第一版运营视图。

## 2. 43 个样本的来源

代码在 `App.vue` 中分别调用：

- `direct_image.list({ limit: 20 })`
- `direct_video.list({ limit: 20 })`
- 动画流程列表 `limit=20`

性能记录再从 `managedParentTasks` 构建。实际截图的 43 条可复现为：40 条直发父任务 + 3 条非调试流程；其中直发 36 DONE、1 FAILED、3 CANCELED，流程 2 FAILED、1 CANCELED。

因此“36 成功样本 / 当前筛选 43 个任务”不是全量历史。当前窗口：

- 图片最早创建：2026-07-29 16:58（北京时间）；
- 视频最早创建：2026-07-25 11:05（北京时间）。

两个类别时间范围不同，页面也没有显示起止时间、加载上限或是否截断。

## 3. 指标归因问题

| 当前做法 | 风险 | 应改为 |
|---|---|---|
| GPU 集群抠图统一标“含排队” | 上传、真实排队、GPU、发布回传混在一起 | 使用 SQLite 的 `gpu_control` 四段时间 |
| handshake `queue_depth` 当排队提示 | 这是握手时全局队列深度，不是该任务等待 | `remote_started - remote_created` |
| Cherry 最早 attempt 到最晚 attempt | 把 38–42 小时 worker 空转算成 Cherry 计算 | 同时展示包络、active sum、idle gap |
| 创建到 handshake 标为抽帧/准备 | 本地排队数小时也被归到抽帧 | 增加 extract 与 queue 独立事件 |
| DONE 且存在 postStart 时推断投递 | 可能没有真正的飞书/云盘 ack | 必须有 delivery receipt 才标“已投递” |
| 视频吞吐按任务简单平均 | 小视频与大视频权重相同 | 同时展示任务中位数与 `总帧/总执行秒` 加权吞吐 |
| generic flow 进入样本数 | 流程无阶段时间、且 0 成功 | 流程单独可靠性面板，不混入直发性能样本 |

## 4. 当前页面尚缺的分析维度

1. 全量/时间范围/分页与 cohort 选择：最近 24 小时、7 天、30 天、指定版本。
2. 成功率与失败原因 Pareto，而不仅是成功任务耗时。
3. 秒/帧、Mpixel/s、输出 MB/s 等归一化指标。
4. backend、节点数、实际节点、workflow version、pipeline commit、输入分辨率、并发数分组。
5. 远端真实排队、GPU 执行、回传、解压的分段瀑布图。
6. 重试次数、有效工作时间、空转间隔、worker restart 次数。
7. 节点级帧数、P50/P95 帧耗时与 straggler 指标。
8. 投递回执覆盖率、上传重试、限流和响应码。
9. 数据完整度/可信度：缺时间点、时间线冲突、推断字段应显式标记。
10. 一键流程七步成功漏斗与每步耗时，目前完全不可测。

## 5. 推荐页面结构

### 顶部筛选

时间范围、任务类型、状态、backend、节点数、workflow version、输入尺寸、是否异常、数据可信度。

### 第一屏：运营健康

总任务、成功率、取消率、P50/P90/P99、投递确认率、当前队列、worker/节点健康；所有卡片显示样本数与起止时间。

### 第二屏：分段与速度

- 端到端瀑布：入口、下载、抽帧、排队、GPU、后处理、打包、上传、回执；
- 吞吐分布：本机 vs 集群、节点数、版本；
- 同体量/同分辨率对照，不只看绝对分钟。

### 第三屏：异常与失败

失败 Pareto、MAD/分位数异常、空转 gap、慢节点、重试瀑布、投递异常。每条异常直接给“慢在哪、证据、建议检查项”。

### 第四屏：一键流程

七步漏斗、每步成功率、等待/运行分离、子任务关联及最后一次 heartbeat。流程 0 成功时应突出可靠性故障，而不是继续展示无效的耗时基线。

## 6. 评价

现有分析足够做“最近任务概览”，**不足以做全量审计、容量规划、GPU 归因和异常根因定位**。最急需的不是再增加一个汇总卡片，而是修正样本窗口、补事件时间、拆 active/idle、使用真实远端时间并展示数据可信度。
