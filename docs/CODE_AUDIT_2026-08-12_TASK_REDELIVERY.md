# 2026-08-12 任务来源与完整重发审计

## 范围

- 任务中心飞书来源姓名/头像展示
- 图片、序列帧和视频任务的完整素材重发
- ZIP 内容完整性、原会话路由、重复请求和状态隔离
- WebUI 技能代理认证与服务重载

## 已修复

1. **来源字段泄漏内部代码**：UI 只消费 `display_name` 和 `avatar_url`，不把
   `open_id` 当作显示名；无权限时显示“飞书用户”而不是代码。
2. **历史回执导致假重发**：完整重发直接生成新包并调用飞书发送，不复用原交付
   artifact 的 `DELIVERED` 跳过逻辑。
3. **一个任务拆成多个 ZIP**：视频与序列帧均生成一个完整包。完整视频包包含
   `original_videos/frames/matte/smooth`；序列帧包包含
   `01_original_frames/02_matte/03_postprocessed`。
4. **缺少角色资料被误判不可交付**：后处理缺失时仍返回原始素材与 matte，缺失目录
   内附 README 说明。
5. **重发污染原任务状态**：使用独立 `redelivery` 状态和有界历史，不修改原任务的
   `status/stage/delivery`。
6. **重复点击与并发重发**：请求 ID、活动状态和 worker PID 防止重复提交；处理中的
   主任务禁止重发，避免生成不完整包。
7. **后台进程启动失败后永久排队**：启动异常会原子落为 `FAILED` 并记录明确错误。
8. **WebUI 认证头丢失**：Vite 代理固定从根 `.env` 注入 `SKILL_API_TOKEN`，避免 URL
   rewrite 和滚动重启导致认证头遗漏。
9. **重复信息与滚动闪烁**：空闲任务页移除重复队列；取消整行 hover 变色；重发回执
   不再额外占一行；1250px 左右窗口使用两层响应式布局，消除横向滚动和错位。
10. **上游工作流缺失节点仍进入任务**：启动前对照秋叶 `/object_info` 校验启用节点；
    缺失节点时返回明确名称并拒绝创建任务，避免 GPU 浪费和误标业务失败。
11. **用户资料轮询重复读盘**：飞书姓名头像缓存增加进程内镜像；WebUI 自动刷新不再为
    每一条任务重复读取完整 JSON 文件。
12. **并发重发竞态**：重发请求创建过程串行化，在活动状态和 PID 检查之外阻止两个
    同时到达的请求各自拉起 worker。

## 权限与隐私

- `contact:contact.base:readonly` 用于识别用户；`contact:user.base:readonly` 用于姓名头像。
- 应用可访问范围必须覆盖实际用户，权限变更后必须发布应用版本。
- 收件目标只来自任务持久化的 `chat_id`，UI 不接受任意目标，降低误发风险。
- 姓名头像保存到运行数据缓存，不提交 Git；代码日志不新增用户标识输出。
